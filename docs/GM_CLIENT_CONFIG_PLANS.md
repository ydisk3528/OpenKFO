# GM 客户端配置（2026-09-27）

## 入口与操作
打开 GM管理器.exe，进入「客户端配置」。分为武器、特效、地图、装备与道具、打包发布。

1. 选择基础 config.spf2 和资源所在游戏目录。
2. 读取配置，选择记录，修改后「保存为独立方案」。每条记录独立 JSON；武器招式每把武器一个方案。
3. 在「打包发布」勾选方案，填写新版本号，公告可空白。
4. 先预览变化、检查资源，再生成 OSS 更新包。生成不会上传，不会替换游戏文件或重启服务器。
5. 将生成的 ZIP 交给现有 OSS 发布工具上传。服务器版本/地图开放配置仍需单独核对，此页面不会部署服务器。

商城上架、价格、期限、推荐排序继续使用「商城配置」。客户端定义与商城销售配置分开管理。

## 保存与备份
方案目录显示在页面底部，位于服务器项目 runtime-local/client-config-plans。
weapons、effects、maps、items 分目录保存；同一记录再次保存更新原方案，同时留存 backups。
releases/版本号 保存合并后的 config.spf2、基础文件备份、方案快照、检查报告和 OSS ZIP。
基础文件不会被覆盖；同名输出版本不能覆盖。重新生成请换版本号。

## 依赖和版本
地图方案自动携带目录、缩略图并刷新资源 MD5；武器方案检查已引用动作/特效的资源登记。
已识别的资源文件引用会继续追踪；无法匹配或重复匹配时报错。其他资源可填写 Data/ 相对路径补充。
生成时只读获取当前 OSS 清单，将本次文件与历史引用合并，旧文件不需要重复放 ZIP。不要删除 OSS 上历史版本资源。
生成包仍需使用 OSS 发布工具检查与上传；没有执行上传测试。

## 当前边界
当前是已有记录的分类编辑与合并，不包含新增地图/武器编号向导、3D资源编辑。
武器招式按钮打开原有武器编辑器，读取其当前游戏目录。保存方案会显示在本模块；若与选定基础不同，打包会明确拒绝，需先核对基准。
高级记录编辑展开时只使用完整记录内容，上方字段的修改不参与保存。
更换音乐频道使用现有音乐配置；新增音乐资源需额外配置和附带资源。
