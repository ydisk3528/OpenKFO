# 服务器模块边界与本次排查

## 状态

整体模块化采用现有 Go 单进程逐步整理，不等同于拆成微服务。
本文件是边界约定，不能当成已经完成全部模块拆分或 Redis 接入。

|模块|状态的所有者与边界|
|---|---|
|账号与会话|登录、在线会话、封禁；其他模块通过接口查询，不直接更改会话表|
|玩家与资产|背包、余额、期限；所有增减走事务与幂等回执|
|大厅与房间|频道、成员、房主、邀请、解散；GM 只能提交管理操作，不能直接修改内存|
|战斗|每个房间串行维护战斗状态，跨房间高频同步互不等待；网络写入和磁盘写入移出状态锁|
|过关与结算|事件进度、结束报告、奖励事务、结果发送、客户端确认分别记录|
|商城|上架、价格、规格、推荐排序；购买调用资产事务|
|配置与版本|配置快照、版本验证、发布、热更新边界|
|运营|GM、通知、批量发放、操作审计|
|基础设施|MySQL、Redis、网络发送队列、日志队列及监控|

先完善当前结算和诊断，再逐项移动职责；不在故障排查中同时重写所有锁与存储。

## Redis

线上安装 Redis 7.2.14-2.alnx4（阿里云 Linux 4 官方更新源）。
本机 127.0.0.1:6379，密码认证，maxmemory=1gb，noeviction，AOF everysec。
配置 /etc/redis/redis.conf，凭据仅在主机 root 私有文件，不入库。
本次仅安装并调整容量，未让游戏读写 Redis。

后续优先用于可重建共享缓存。每个缓存必须明确 MySQL 数据来源、失效机制、超时和断连回退。
余额、背包、领取回执仍以 MySQL 事务为准。不要用 Redis 全局锁控制战斗。
noeviction 达到上限会拒绝写入，接入时必须处理错误；不可用缓存写失败来回滚已完成的资产事务。
