# 百宝奖池配置

GM「装备与商城 → 百宝奖池」管理普通百宝券（75）和节日百宝券（76）两个独立奖池。配置券数、奖励权重、物品规格、金币与点券。

刷新从总奖池等概率选择6个不同条目。权重只控制这6格中的最终中奖概率，不控制出现概率。每格必须是单种奖励：一种物品规格、金币或点券；组合奖励在游戏编码时拒绝。新物品规格默认1份、限时物品7天，已有规格沿用原数量和期限。

## 线下实验接入（2026-09-29）

`experimental_treasure` 启用19100/19110刷新与19120/19130抽奖。客户端点击位置不决定奖品：服务器校验组号和六个打乱后的条目标识，按服务器保存的权重选中奖项。物品规格在刷新时快照，GM随后修改不会更换当前组奖品。

普通百宝每组六格最多抽3次，节日百宝最多6次；刷新开启新组。普通与节日券分开扣除，跨有效券堆扣券；关闭窗口的19120/0不消费。扣券、发奖和treasure_draws回执在同一事务中锁定账号完成，失败回滚。相同请求重放不重新抽奖、不重复扣券；已翻开的卡不重复发奖。重连须刷新新组，历史结果已存数据库。19160历史展示尚未接入。

测试覆盖单元筛选/回包和独立MySQL并发8次确认、券不足、无效物品回滚、7天武器期限、金币点券到账及溢出回滚。游戏客户端结果动画、仓库与券数显示仍需线下实测；未部署线上。

配置表treasure_rules/treasure_rules_audit；抽奖流水treasure_draws。更新服务器首次启动自动建表。GM预览仅模拟，不扣券发奖；管理界面旧版的“待接入”文案不代表服务器实验开关状态。

## 连续翻牌修复（2026-09-29）
取消单组一次限制。每张卡最多抽取一次，普通百宝第三次结束本组，节日百宝第六次结束。每次消耗基础券数乘本组抽取次数。每张卡稳定编号作为组内幂等键；已中奖奖项不再参与本组后续加权抽取。结果包保留卡牌编号，仅更新对应奖品内容和已翻开标记，不再交换编号。连续六次、重放、显示奖品与发奖项目一致的测试通过；客户端实际显示仍待复测。

## 图标与普通三次上限修复（2026-09-29）
原生道具显示经85BA40查询1550目录：百宝35字节条目的+18必须填写奖励规格键，对应108字节目录的+9；真实道具编号位于目录+5。此前误填真实道具编号且漏发目录，导致图标查询失败。刷新时先发送奖励目录1550，再发送19110；使用已快照的物品规格，复用称号奖励目录构造与冲突检查。
普通百宝19110的+1设置为3，事务也独立限制最多三次，第四次请求在扣券前拒绝。独立MySQL测试验证目录编号、三次扣券、第四次拒绝及重放。修复版已构建并替换线下UI服务器目录；客户端图标和第三次结束动画仍待验证。节日六次抽取及重放已通过独立MySQL测试。
