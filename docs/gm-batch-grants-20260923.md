# GM 批量发道具

入口：GM 左侧“批量发道具”。可搜索名称/编号，添加多种道具，各自指定数量和限时物品期限；选择指定用户或全部用户。

保存批次只冻结名单和道具，不立即发放。检查摘要后点击“开始 / 继续未成功用户”。页面显示已处理人数、成功/失败/待处理、累计道具数量、当前账号，以及每人的结果与错误原因。暂停在当前用户请求完成后生效。

关闭 GM 或连接中断后，从“历史批次 / 恢复进度”打开同一批次继续。不要为补发另建新批次。历史入口列出最近 200 批；数据库保留所有批次。

## 持久化与一致性

- `gm_grant_batches` 保存编号、请求哈希、道具快照和创建时间。
- `gm_grant_recipients` 保存固定用户名单、状态、错误、发放后的物品记录及更新时间。
- 每用户锁定批次行和账号行，在同一事务发整组道具并记成功；任一项失败则回滚整组。失败原因另行保存，不覆盖成功状态。
- 同一批次/用户成功后重试不再发放；未收到成功响应也可安全重试。
- 全部用户名单按创建时冻结，新注册用户不自动加入。批次内容不能改动，防止断点继续时内容不同。
- 可堆叠物品合并未失效堆栈，单栈超过 999 时整组失败；非堆叠物品按数量创建独立实例，不跳过已有同款。
- 每批 1–100 种道具，每项 1–999，每人总计最多 5000 件。限时物品使用现有 GM 模板期限规则。
- 重新登录刷新客户端背包。暂停/关闭 GM 不删除服务器记录。
