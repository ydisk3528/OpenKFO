# 统一发布版本（尚未部署）

唯一玩家发布版本来自 OSS `version/version.json` 的 `version`。

## 一次性启用

部署新版服务器及新版启动器完整更新包后，在服务器 config.json 增加：

```json
"release_version_url": "https://openkfo.oss-cn-hangzhou.aliyuncs.com/version/version.json"
```

删除旧的 `required_client_release` 配置。它只为未迁移部署保留兼容读取，不再用于新发布。
首次启用需替换并重启服务器。取消每30秒轮询和启动时查询，改为账号认证成功、会话建立前读取上述OSS版本文件；启动器打开时的检查保留。没有玩家登录时不请求OSS。
登录查询失败时保留最后成功版本；若也没有任何已知版本（或兼容配置），本次登录返回服务器配置暂不可用，不误报玩家版本过旧。查询在状态锁外执行，最多8秒。
开战仅比较内存中的最新已知版本，不请求OSS；其他玩家登录获知新版本后，旧版本玩家下一次开战仍会被提醒更新。已进行中的战斗不中断。
线下测试服不配置这个URL，也不设置 required_client_release，以免被线上发布影响。

## 玩家行为

新版启动器仍强制更新，无跳过；只有启动器文件和游戏文件均校验通过，且两份清单的版本相同，才上报该OSS发布版本。编译时LAUNCHER_VERSION只是构建标识，不再作为OSS更新后的游戏发布版本。

旧版本可以正常登录大厅。在大厅第一次房间列表查询时发送聊天文本：
当前游戏版本过旧。请使用新的登录器 更新到最新版本

旧版无法准备或开战；队伍内有旧版参战者，房主也不能开战。已经进行中的战斗不强行中断，下次开战重新检查。

## 文件校验

config.spf2 的 SHA-256 仍用于文件完整性和服务器内部地图配置一致性，不是另一套玩家发布版本。
本次新增启动检查与登录时兜底会识别服务器内部地图目录未同步。发布地图配置时仍需同步对应地图目录及资源，不能只修改哈希冒充同步完成。

## 发布顺序

1. 先完成服务器地图配置/资源兼容性验证，并备份。
2. 上传不可变的完整更新清单及资源（包含新版启动器和网络桥）。
3. 验证对象可下载及哈希正确，最后切换 OSS version/version.json。
4. 服务器读取新版本后，新登录及下一局开战按同一版本校验。

当前仅代码、测试与本地构建完成；没有上传OSS、修改线上配置或重启线上。
