# 商城配置读锁优化（未部署）

购买、赠送原来对商品、出售期限和同一条 VIP 规则使用排他锁。它们没有修改这些配置，却阻塞其他玩家读取。现改为共享锁，配置写入仍需等待交易结束；玩家账户、背包、交易回执的事务保护保持不变。续费读取商品和期限同样使用共享锁。

VIP 折扣展示改为显式 REPEATABLE READ 只读事务，避免仅查看商城也锁住账户。实际购买、赠送仍在自己的事务中重新验证会员、价格、余额及请求，不使用展示结果授权扣款。

## 验证

- 独立数据库 `openkfo_debug_shop_locks_1790489845`，不修改线上或线下玩家数据库。
- `TestShopSharedReadsLocalDatabase`：持有第一位玩家的账户写锁及商品、期限、VIP 规则共享锁时，另一玩家成功购买；同账户折扣展示不阻塞。
- 商品上下架、期限、VIP 规则写入不能绕过进行中的共享读锁。
- 重复购买回执不重复扣款；下架后新购买被拒绝且余额不变。
- `TestVIPShopPurchaseLocalDatabase`：正常购买、赠送、过期会员、改价后的旧请求拒绝、重复回执和金币分支通过。

这解决的是数据库中的额外串行点，不代表大厅调度已全部改成并发，也不代表已证明线上战斗延迟消失。Redis 排行榜候选一并保留；本次没有增加商城价格缓存，没有重启线上。
