# 功夫小子 GM管理器

Flutter GM 管理界面：Windows 完整版包含本地/线上管理及本机武器编辑；macOS、Android 使用 HTTPS 线上版入口。

关卡页面显示目标服务器资源版本和关卡绑定版本。版本不一致时禁止保存；本机目录与目标服务器不同也不能直接导入。武器/客户端发布程序会比较新旧地图、脚本和怪物模板：一致时在事务内保留关卡设置和玩家解锁记录并更新版本绑定；有变化时阻止发布，需要先核对关卡配置。服务激活失败时回滚发布清单和未提交的数据库迁移。升级此功能须同时部署新版管理后端与 `update-publish`，只更新 GM 界面不够。

GM 不再自动下载安装更新。管理命令携带 GM 版本号，后端验证不匹配时拒绝执行，并提示更新代码、重新编译最新版本。登录器的 OSS 更新渠道不用于 GM。

左侧选择“本地测试服”或“线上服务器”，账号、背包、商城、钱包、战斗奖励请求统一使用所选环境。Windows完整版每次打开默认本地测试服（独立线上入口仍仅连接线上）；切换时清空所选账号和待提交操作。武器方案可以应用到本机客户端，或通过“更新到线上”发布给玩家。

武器配置列表显示客户端小图标，支持按名称/编号搜索和刀类、剑类、长柄、拳套、拳脚、重型、奇门类型筛选（取自 item.txt 类型字段）。右侧上方显示武器简介，下方保留连招、伤害和 BUFF 编辑。缺失图标显示占位图，缺少类型或简介时明确提示；筛选不会修改或保存武器方案。此界面需配套新版 kungfu-desktop-admin.exe 返回图标、简介和类型。

“战斗奖励”分别设置胜利、失败、平局的经验和金币，0 表示不发放，范围 0–1000000。读取失败不能保存；配置版本冲突必须重新读取。保存至对应 MySQL 的 `battle_reward_rules` 表，新版 Go 服务器在下一次结算读取，不需要重启；历史对局不补发。首次启动新版服务器仅在数据库没有配置时导入 `config.json` 的 `settlement`，以后 GM 配置优先。升级默认关闭，填写曲线后可启用；升级礼包、新手引导奖励及战斗武器掉落均需在 GM 中单独配置。

本地模式连接回环地址上的独立 MySQL 实例，库名统一为 `kungfu_game`；线上模式使用 SSH。两种模式的配置见下文，连接失败不会自动切换环境。

## 直接构建（Windows x64）

在本目录执行，不需要 PowerShell 打包脚本：

```text
flutter pub get
flutter build windows --release
```

输出：`build/windows/x64/runner/Release/kungfu_item_manager.exe`。需要 Flutter SDK（Dart ^3.13.2）和 Visual Studio 的 C++ 桌面开发工具；建议使用英文源码路径。

界面调用 Go 管理后端，从仓库根目录执行：

```text
cd server/go-server
go build -ldflags "-H windowsgui" -o ../../gm/build/windows/x64/runner/Release/kungfu-desktop-admin.exe ./cmd/desktop-admin
```

把整个 `Release` 目录复制为仓库根目录 `dist/GM管理器`，可把 `kungfu_item_manager.exe` 改名为 `GM管理器.exe`。保留所有 DLL、`data/` 和 `kungfu-desktop-admin.exe`，直接双击打开。

## macOS / Android 线上版

在本目录执行 `flutter pub get` 后，选择目标平台命令：

```sh
# 在 Mac 上构建，需要 Xcode
flutter build macos --release --target lib/main_online.dart
```

产物：`build/macos/Build/Products/Release/OpenKFO-GM.app`。

```text
flutter build apk --release --target lib/main_online.dart
```

Android 可在 Windows/Linux/macOS 上构建，需要 Android SDK 和兼容 JDK（工程 Java 目标 17）。产物：`build/app/outputs/flutter-apk/app-release.apk`。AAB 命令为 `flutter build appbundle --release --target lib/main_online.dart`，产物在 `build/app/outputs/bundle/release/`。目前默认开发签名用于测试，正式分发前配置自己的签名；macOS 的签名与公证也需自行准备。

此入口不调用本机 Go EXE，不读取下述 Windows SSH 配置。先部署 [GM HTTPS API](../server/go-server/README.md#gm-https-管理接口)，打开应用填写 `https://管理域名/gm/api` 和管理令牌。令牌只保留在当前会话；返回连接页可换服务器。

账号、背包、道具发放、商城、钱包、奖励表使用同一线上服务；不显示本地切换与武器编辑。商城图片由新版 GM API 按商品编号读取并返回，不暴露服务器文件路径；服务器需自行提供客户端图标资源，缺图显示占位图。道具文件导出停用，奖励 CSV 使用文本复制/粘贴。手机可横向、纵向滑动宽表格，建议横屏操作。macOS 工程需在 Mac 上完成实机构建验证。

以下运行配置适用于 Windows 完整版。

## 运行配置

在 EXE 同目录创建 `gm-settings.json`，将示例路径替换为自己的路径：

```json
{
  "root": "C:/kfo-runtime",
  "local_settings": "C:/kfo-runtime/settings.private.json"
}
```

`root` 中需有 `runtime-local/client`，供读取客户端的道具与武器配置。若不写 gm-settings.json，可用 `--root <目录>`、`--local-settings <文件>` 指定；自动查找模式依赖上级目录的 `runtime-local/online-admin.json`，仅用本地模式也建议显式配置 root。

本地模式的 `settings.private.json` 至少包含：

```json
{
  "dsn": "kfo:替换为自己的密码@tcp(127.0.0.1:3306)/kungfu_game",
  "database": "kungfu_game"
}
```

先启动 Go 服务器初始化表。可以使用本机 MySQL，或已经建立的本机 SSH 转发；GM 不负责建立数据库隧道。本地、线上均可使用 `kungfu_game`，但必须连接不同 MySQL 实例；本地连接地址必须为回环地址。Windows 服务器双击模式仅在需要 SSH 转发时填写 `ssh_config`，见 [Go 服务端说明](../server/go-server/README.md)。

线上模式在 `root/runtime-local/online-admin.json` 中填写：

```json
{
  "host": "your-server.example",
  "port": 22,
  "user": "your-admin-user",
  "key": "C:/Users/your-user/.ssh/kfo_admin"
}
```

需要本机 OpenSSH 客户端、已验证的 SSH 主机密钥、服务端 `/opt/kungfu-go/kungfu-admin`；服务器 `/etc/kungfu-go/game.env` 提供 `KK_MYSQL_DSN`，SSH 账号须具备后端所需的 `sudo -n` 权限。配置和密钥不要提交仓库。

## 1–150 级成长与奖励（2026-09-18）

GM 直接双击 `dist/GM管理器/GM管理器.exe`；整个文件夹保留，不需要 CMD。
本地与线上分别存储在各自数据库的 battle_reward_rules，revision 防止覆盖并发修改。
旧六项奖励首次读取时展开为 150 行，金额保持原值，自动升级默认关闭。

每行：level、next_experience、win_experience、win_gold、loss_experience、loss_gold、draw_experience、draw_gold。
单局奖励 0–1000000，升级所需经验 0–2147483647。150 级升级经验必须为 0。
启用自动升级前必须填写 1–149 级所需经验；这是自定义曲线，不是原版规则。
批量编辑留空保持原值，0 清零；编辑或导入只改草稿，点击保存才写入当前环境。
CSV 使用 UTF-8 BOM，可用 Excel 打开；先导出模板，编辑后以 UTF-8 CSV 保存，导入时填文件完整路径。
CSV 不包含自动升级开关。复制线上使用本地已保存配置（包括开关），展示所有差异并确认后才写入，线上 revision 变化会拒绝保存。

奖励按 4080 发送前快照的等级选择；旧角色等级 0 按 1 级奖励处理。结算事务内发奖、扣除升级所需经验、连续升级至最多 150 级。满级仍可获得金币与经验，经验字段上限为有符号 32 位整数。重复结算按 battle_settlements 日志返回原结果，不重复发奖。
GM 保存从下一次结算生效。武器掉落和称号未启用。
客户端经验条分母来自客户端自己的等级表；自定义曲线暂未同步到客户端资源，进度条比例可能不同，等级和服务端经验按本表执行。

### 武器动作完整读取（2026-09-18）

招式来源改为 itemact.txt 全部非零动作，combotip.xml 仅用于按键标签，不再决定招式是否显示。
读取动作所属的 animation/*.xml，处理带前导零的动作编号；默认显示战斗招式和可编辑动作，可勾选显示移动、受击等其他动作。
没有连招提示文件时显示状态编号，不猜测原版按键。没有直接命中属性、定义不唯一或含非敌方效果时显示原因，不强行写入。
多个武器或招式共用的动作在应用时复制为独立动作，只修改当前武器对应状态的 itemact 映射，命中属性也复制，避免影响原动作及其他武器。优先使用动画表中未使用的三位动作编号；空间不足会拒绝写入。
伤害、BUFF 等仍只修改本机客户端配置；保存方案不等于应用，游戏须关闭后才能应用。配置包有备份及无关文件校验。新增招式实战表现仍需测试。

商城批量改价：勾选商品（可先搜索，再选择搜索结果），点击“批量改价”，选择金币或点券并填写统一售价。仅更新已有销售记录，保留期限、数量、上下架及其他标记；同一商品的多条规格统一改价，未配置商品跳过并显示数量。本地和线上使用相同操作，确认框显示目标环境。推荐／优惠标记待客户端协议核实后接入。

商城装备可勾选“购买后按上述天数到期”，设置1–3650天的服务器期限；不勾选则之后购买的实例在服务器永久有效。该设置不改已有库存的期限，批量改价及上下架也不改变期限策略。旧配置默认保持永久，客户端显示天数不自动转成真实失效时间。目标环境需要更新服务器与GM管理接口；若旧接口没有确认期限保存，界面会明确报错，其他商品字段可能已保存，应刷新核对。

商城采用分类、连续滚动商品网格和右侧配置面板，不包含人物试穿。鼠标滚轮或拖动滚动条即可浏览全部商品；卡片只构建可见区域和少量预加载区域，不一次创建全部商品控件。商品图片按 `item.txt` 中的图标路径读取 `runtime-local/client/Data/UI`，按当前可见区域分批加载（单次最多 24 张），滚动停止后短暂合并请求，图片缓存最多保留 256 张。支持标准 PNG，以及能够唯一还原图片头的旧客户端 PNG；文件缺失或格式不确定时显示占位图。Windows 版使用本机客户端资源，HTTPS 线上版使用 GM API 所在机器的资源。原客户端图片不随源码或安装包分发。切换分类不会清空已勾选商品，批量操作前请核对已选数量。

武器动作名称：优先显示该武器的连招配置；没有匹配标签时读取原动画起始说明并标明“动画说明”。共享动作可能保留原开发名称与尾部数值，这不是完整按键或正式招式名；没有可靠说明时显示“按键映射待核实”。

## 自身状态（AddBuff）的「作用对象」

「防护 / 自身状态」卡片里的 `<AddBuff Scope>` 是**作用对象**（不是范围），档位定义出自 `animation/2001.xml`
文件头的策划说明注释，界面已改成下拉：

`1` 对自己使用 ｜ `2` 对自己包括队友使用 ｜ `3` 对自己包括队友使用（Param1=范围）｜
`4` 对敌人不包括自己 ｜ `5` 对敌人不包括自己（Param1=范围）｜ `6` 对死亡的队友中等级最高的人使用

**Param1 才是范围**，只有 `3` 和 `5` 用得到（其它档位该字段会被禁用）。数据里出现过未收录的 `Scope="40"`
（`animation/2204.xml` 的 `149`/`964`/`965`），界面会把它显示成「未收录（原样保留）」而不是偷偷改掉。

顺带：给一个招式挂**两个不同 debuff** 时，招式级「BUFF」下拉只能给一个，第二个用这里加一条
`Scope=4/5` 的 `AddBuff` 即可（按帧直接作用，不占命中属性）。

## 武器连招分组

武器配置按客户端 `combotip.xml` 的完整按键路线分组（如 CCCXX）。展开路线后，点击“第 N 段”编辑该动作的命中伤害、BUFF与持续时间（毫秒，3000=3秒）。动作段不等于一次命中，一个动作可能引用多个命中属性。

不同路线引用同一状态时共用一份配置，切换路线不会生成重复规则。提示文件未覆盖的动作放在“其他动作”；提示中的状态若没有实际动作，则不能编辑。没有独立提示文件的武器仍保留全部动作，不根据动画注释猜测按键。保存/应用仍使用原状态编号，已有方案保持兼容。

## 基础任务模板与奖励配置

先在主界面选择本地或线上，再打开“任务配置”。桌面版可点击“读取客户端模板并补充缺项”，从本机已配置客户端的 BaseQuest 读取任务编号、名称、说明、条件和后续关系。只新增缺少的任务，已有条件、奖励和开关保留；重复读取不会重复添加。新任务默认关闭、经验金币均为0，编辑并点击“保存任务配置”后才写入所选环境，读取模板本身不会修改服务器配置。

列表显示客户端任务名，编辑窗口显示任务说明。原始奖励字段的币种及物品发奖链尚未完整确认，因此不会自动导入为经验、金币或物品奖励。当前只支持参赛／胜场类条件完成，连击、歼敌等条件仍待接入。纯在线移动端没有本机客户端资源读取按钮，可继续编辑已有任务配置。

新版服务器支持手动指定“奖励商品编号”（0表示不发道具）。填写商城的商品编号，不是道具配置ID；每项任务发放一份对应商品规格，不扣玩家余额。接取时保留这个商品编号，领取时按该商品当前记录和服务端有效期发放。商品关闭、不存在或记录异常时整笔任务奖励回滚，修正后可以重新查询领取；不会只扣掉任务机会。库存、经验金币、完成状态及领奖回执同事务，重复查询不重复发放。需要配套新版服务器，旧版不会处理新增物品字段。

## VIP管理

先在主界面选定本地或线上环境、玩家，再打开“VIP管理”。可查询当前资格，发放白银、黄金、铂金会员卡，期限为1–3650天或永久。每次确认新增一张卡，不延长旧卡；最高有效档位优先，同档永久优先，否则取最晚期限。发卡后重新登录刷新，目前只开放VIP身份和期限，额外折扣、奖励未开放。

发放失败或超时后保留当前页面，使用“重试同一请求”，请求编号和参数保持不变，服务器不会重复发卡。结果未确认前页面禁用编辑和返回；不要通过重开GM发起第二笔操作。关闭进程不会保存这笔待确认请求，请先记录页面显示的请求编号，交给管理员查询desktop_admin_operations审计后再处理。

需要配套新版服务器及管理后端。会员卡到期后在大厅/等待房的库存刷新中降档；战斗中沿用现有安全刷新边界，结束回房再刷新显示。此基础功能不代表VIP全部权益已经实现。

## 荣誉规则

“荣誉规则”管理所选本地/线上环境的胜负平积分、计分模式编号、等级门槛和期次。仅已配置模式且至少两人的有效结算累计积分；取消全部模式停止累计，历史记录保留。等级门槛最多10项、严格递增，留空关闭分级；调整门槛也会改变历史资料显示等级。

期次只能追加，旧期名称与顺序不能修改，避免期号关联到错误的历史战绩。新增期成为当前期；积分从下一次结算读取，资料查询即时读取，客户端期次目录需重新登录刷新。这是自定义积分规则，不代表原版数值或完整挑战匹配已实现。

新版服务器首次启动把原config.json的honour导入honour_rules，后续启动不覆盖GM修改。尚未完成导入时GM拒绝读取和保存，避免空配置覆盖旧期次。保存有版本冲突检查与同事务审计，需要配套新版服务器、GM后端。

## 关卡开关

选择本地测试服或线上服务器后，打开“关卡开关”。先读取并保存客户端地图目录，然后按地图名称选择“开放”“关闭”或“原规则”；也可点“全部开放”“全部关闭”“恢复原规则”。点击“保存关卡开关”后生效，配置不会自动同步至另一个环境。

新版服务器在新建房间、修改地图、开始战斗时检查配置，随机选图也会排除关闭项；已进行的战斗不会被强制中断。明确设置“开放”会跳过该地图的称号和个人解锁条件，在已实现的房间模式中允许目录内的指定地图；“关闭”优先于全部开放。“原规则”保留默认地图池和进度限制。客户端关卡列表和开战准入使用这些规则，但不会实现尚缺失的 PVE 敌人、脚本或玩法。

读取失败不能保存；其他管理员已修改时会拒绝旧版本保存，需重新读取。配置变更与修改前后审计在同一数据库事务提交。需要配套新版Go服务器及GM管理后端，单独更新界面不会改变旧服务器行为。

## 已持有物品的服务器期限

选择本地或线上环境、玩家及已持有物品，在详情中点击“修改服务器期限”。支持从现在起1–3650天，或将尚未失效的实例设为永久；只影响所选实例，不批量修改同名物品。已失效物品不能通过此入口恢复。修改有事务审计与请求幂等校验。

此设置为服务器UTC到期时间，不是客户端原来的365+显示字段；客户端文字暂不改变。需要配套新版服务器处理到期状态与在线通知；仅升级GM不会让旧运行服务器自动失效。线上使用前需部署对应GM后端与服务器，本轮未改线上。

## 奖励物品与升级礼包

在同一个 GM 中选择本地或线上，再进入“战斗奖励”：

- “奖励物品定义”：按客户端物品名称搜索、添加发放规格、修改服务器到期天数。新增规格默认1份，限时装备默认7天；无需填写内部编号。商城下架、改价不会改变已建立的奖励模板。
- “升级礼包”：填写到达等级（2–150级）、金币、点券，按名称选择武器、道具或装饰称号。每级最多8件，全部等级合计最多150件；金币、点券每项0–1000000。应用到草稿后点击“保存奖励配置”。空列表不发礼包，已有等级不补发。
- “新手引导奖励”：使用同样的名称选择和金币、点券配置。完成原生新手引导后自动全部发放至背包和钱包，每个角色仅一次；空配置不发物品或货币。配置不会替已有角色补发。
- 同一奖励包内任一物品失效或余额越界，会整包回滚。升级、引导、任务奖励经统一 RewardManager 发放，库存归 InventoryManager、货币归 WalletManager。装饰称号是背包物品，不是成长称号等级。
- 普通任务、扩展任务、称号选择、战斗掉落中的旧奖励编号继续使用，不需要逐条修改。战斗掉落仍仅支持原有武器规则。
- 成长 CSV 不包含礼包、引导奖励或物品模板；导入 CSV 会保留当前这些配置。跨环境复制奖励规则前，确认目标环境存在内容一致的物品定义。

新版服务端启动时创建并迁移独立物品定义表。线上使用前需部署对应服务端与 GM API/管理后端；本地构建不会自动部署线上。

GM 左侧菜单可上下滚动，底部关卡、荣誉、VIP 等入口可滚动到达。

GM 不再自动下载或安装更新，也不再提供更新菜单。当前管理协议版本为 `1.1.0`，启动检查 `gm_version`，每次提交附带该版本；服务器 HTTP/SSH 管理入口不匹配则拒绝执行，请更新源码后重新编译。关卡开关页显示事件/波次计划是否存在，并提供同环境的关卡奖励入口。已有计划不等于所有地图都可运行；缺少计划的地图需先导入验证。

关卡配置：侧栏独立入口，可按地图名称或编号搜索，勾选后批量开放/关闭，再点击保存关卡开关。每张地图的「配置奖励」可直接保存通关/失败经验、金币、点券和物品；奖励图片可点击放大，物品可按名称搜索。奖励保存使用版本检查并保留其他地图、升级礼包等配置。开放开关不会自动生成缺失的闯关计划。

## 招式帧轨道与攻击范围（2026-09-28）

「连招与命中效果」里每个招式右侧新增「帧轨道与攻击范围」入口（时钟图标）。

帧数：动作块 `<AnmDesc>` 几乎都以一条 `endframe=99`（少数 999）的尾巴片断收尾，那只表示「保持姿势直到被中断」，不是时长。现在显示的是该招式引用动画 `Data/animation/*.anm` 自己的帧数（读不到动画时才退回动作块的最大 endframe，并标注「动作块估算」）。弹窗里的轨道按真实帧数铺标尺，并用一条竖线标出真实结尾——尾巴片断会明显超出这条线。

轨道上同时画出每一段 `<Anm>` 片断（含动画名与帧数）以及特效、命中特效、音效、接招窗口、防护、招架等标记。

攻击范围：每段 `<Anm>` 片断的子元素 `<AttackScope>`（以及人物盒 `<CharScope>`）可编辑，六个属性 `centerx/centery/centerz` 与 `length/width/heigth`，分别对应左右、上下、前方与纵深/宽度/高度。右侧预览在**带 XYZ 坐标轴和刻度**的平面图上叠画攻击盒（青）、人物盒（灰）、以及本招式里的**力场盒（`<ForceField><ScopeBox>`，橙）与投技盒（`<LockedAttackSwitch><Scope>`，紫）**；两个视图都是标准正交投影——侧视横轴 Z 前方／纵轴 Y 上下，顶视横轴 X 左右／纵轴 Z 前方。原点 (0,0,0) 在角色脚下，所以 y=0 那条线就是地面；盒子按中心±尺寸/2 画，y 很低的盒子确实会沉到地面以下，画出来就是为了让人一眼看到。预览下方列出各盒的六个数值，方便对着图核对。片断原本没写攻击范围时空着不提交；改过才写入。

保存只写入编辑集；回到武器页点「应用到游戏」才写进客户端配置包。动作块被多把武器共用时会自动克隆成当前武器独占，不影响其它武器。此功能需要新版 `kungfu-desktop-admin.exe`（`weapon_stage_track` / `weapon_scope_set`），GM 界面与后端要一起更新。

后续扩展（未实现）：为单个招式自行上传动画与音效。
